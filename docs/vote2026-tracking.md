## 1. 実測で確定した事実

### 1.1 公式サイトから取れるもの・取れないもの

公式サイト（`https://idolmaster-official.jp/cinderellagirls/vote2026/`）は
Next.js の静的エクスポート。

- **アイドル辞書は取れる。** 投票対象190名の全データがJSチャンク内にJSON配列として
  そのまま埋め込まれている。HTMLのスクレイピングすら不要。
  `slug`（公式のキー名は `idol_code`）、公式表記名、かな、英語表記、属性、
  イメージカラー、公式の並び順IDが揃う。
- **中間発表も得票数も存在しない。** `/system` のスケジュールにはミッション期間・
  引換期間・投票期間の3つしか記載がなく、中間発表の予定はない。アイドル個別ページも
  票数表示のない静的シェル。`api.idolmaster-official.jp` にも公開の集計
  エンドポイントは見つからなかった。**一次情報での代替は不可能。**

### 1.2 報酬の段階閾値（`/achievement`）

| 順位 | 報酬 |
|---|---|
| 1位 | 専用特別衣装＋ブックレット |
| 上位5名 | xRライブ出演＋新規楽曲＋専用衣装 |
| **上位7名** | **新ソロ楽曲＋カバー楽曲＋ソロアルバム「M@STER ARTIST」** |
| 上位15名 | ちびぐるみ |

**順位は連続値ではなく3つの崖。** 8位と9位の差には実質的な価値がない。

### 1.3 佐藤心の歴代実績（`/history`）

| 回 | 順位 |
|---|---|
| 2017 | 9位 |
| 2022 | 8位 |
| 2023 Stage for Cinderella 予選グループB | 1位 |
| 2023 Stage for Cinderella 本選 | 6位 |

3回連続トップ10、ただし5位以内は未到達。**ちょうど7位ボーダーの上。**
→ 追跡すべき問いは「上位10名の順位推移」ではなく **「7位以内に入れるか」**。

### 1.4 公式シェア投稿のテンプレート

```
佐藤心 さんに投票しました！

▼公式サイトで投票しよう！
https://t.co/xxxxxxxx   ← 展開先 /cinderellagirls/vote2026/vote/idol/sato_shin

#シンデレラガール総選挙2026
```

- **名寄せは本当に不要。** 190名の公式表記名は全てユニークで、
  **ある名前が別の名前の部分文字列になるケースもゼロ**（`generate_idols_json.py`
  が毎回この2点を検査し、崩れたらエラーで止まる）。
- スラッグは6名が「姓_名」形式ではなく単一語：
  `anastasia` / `clarice` / `kate` / `natalia` / `helen` / `layla`。
  抽出用の正規表現 `/idol/([a-z_]+)` 自体は問題なく動く。

## 2. Yahoo!リアルタイム検索の実測仕様

LINEヤフーはXの正規データライセンス保有者。ログイン不要・無料。
**`search.yahoo.co.jp` は環境の承認ドメインに追加済み。**

### 2.1 アクセス方法

```
GET https://search.yahoo.co.jp/realtime/search?p={query}&rkf=3&b={offset}
```

HTMLの `<script id="__NEXT_DATA__">` 内のJSONに全データが入っている。
取り出し先は `props.pageProps.pageData`。

| パス | 内容 |
|---|---|
| `timeline.head.totalResultsAvailable` | **件数。これが主指標** |
| `timeline.head.totalResultsReturned` | 返却数（最大40） |
| `timeline.entry[]` | 投稿本体。`id` / `userId` / `screenName` / `createdAt`(unix) / `displayTextBody` / `urls` |
| `transition.showChart` | ツイート数グラフの有無 |

### 2.2 確定した制約（重要）

- **索引の深さは約24時間。** `"佐藤心 さんに投票しました"` の返却分は
  08/17 01:53〜18:17 をカバー。**30日グラフによる遡及はできない。**
  当初 Yahoo で 8/3 以降を遡れると見込んだが、これは誤りだった。
- **`showChart` は全クエリで `false`。** ツイート数グラフのAPIは
  この種のクエリでは提供されない。期待できない。
- **ページネーションは1ページで打ち切られる。** `b=40` 以降は返らない。
  `totalResultsAvailable=89` に対し実際に取得できたのは39件。
  → **件数（推定値）と、40件のサンプルは別物。両方使う。**
- フレーズ検索の引用符はあってもなくてもほぼ同じ結果（89 vs 90）。

### 2.3 実測できた性質

- **投稿数 ÷ ユニークユーザー数 = 1.00**（39投稿が39人から。16.4時間で重複ゼロ）。
  投票報告は日次ミッションなので、1日の中では1人1投稿。
  **日次のツイート数はほぼそのまま「その日投票した人数」の代理指標になる。**
- 全体の規模感（8/17 18:32 時点、直近24時間）:
  - `"さんに投票しました"` → 6,641件
  - `#シンデレラガール総選挙2026` → 12,371件

### 2.4 注意

- Yahooのスクレイピングは**Xの規約ではなくYahooの規約**の問題になる。
  グレーである事実は消えない。**アクセス間隔は1.5秒以上空ける**こと。
- `totalResultsAvailable` は推定値で、取得可能件数を上回る。
  絶対数ではなく**シェア（比率）と時系列変化**として使う。

## 3. 設計

### 3.1 却下した案（再提案しないこと）

| 案 | 却下理由 |
|---|---|
| Google Trends | LIVE出演で検索が跳ね、既存人気と交絡して分離不能 |
| X公式API | pay-per-use移行で非現実的（全期間検索はEnterpriseのみ） |
| 自前スクレイピング（twikit / Playwright） | 規約違反＋アカウント凍結リスク |
| キャラ名の名寄せ辞書 | 不要（§1.4） |
| 第三者X APIでの継続収集 | **Yahooで無料で足りるため不要になった** |
| `url:` 演算子での狭域トラッキング（上位10名のみ） | **分析上成立しない。§3.2** |

### 3.2 モードB（上位10名のみ追う）を却下した理由

技術面以前に分析として成立しない。

- 10名分しか引かないと**総投稿数＝分母が消える**ため、シェアも前日比も出せない
- **圏外から浮上してくる新顔を構造的に検知できない**。7位ボーダーを脅かす相手が
  見えないのは、この追跡の目的そのものを損なう
- 「上位10名が全体の3〜5割」という仮定は観測前には確かめられない
- Yahooは無料なので、そもそもコスト節約の動機がない

**190名全員を毎日引く。**

### 3.3 指標

- **主指標：アイドル別の日次ツイート数シェア**
  （`totalResultsAvailable` ÷ 全190名の合計）。
  抽出条件が一定なら比率は不偏で、絶対数のカバー率に依存しない。
- **副指標：40件サンプルから算出するユニークユーザー数と、URL／本文の一致率。**
  `urls` の展開先から `/idol/([a-z_]+)`、本文から `^(.+?)\s*さんに投票しました` を
  取り、突き合わせる。乖離＝投稿前に本文を編集したユーザー。乖離率はデータ品質の
  警告指標として使う。
- **累積ユニーク author_id は主指標にしない。** 部分標本からは算出できず、
  日次ミッションなので飽和もする。

### 3.4 精度の限界（これが最重要）

シェア4%前後のアイドルについて、二項比率の標準誤差：

| 1日の標本数 | 標準誤差 | 95%信頼区間 |
|---:|---:|---:|
| 1,000 | 0.62pp | ±1.21pp |
| 2,000 | 0.44pp | ±0.86pp |
| 5,000 | 0.28pp | ±0.54pp |
| 10,000 | 0.20pp | ±0.38pp |

上位10名の隣接する2人の差はおそらく0.3〜0.5pp。**1日分では隣接順位は
原理的に分離できない。** 7日プールなら n=14,000 で ±0.32pp まで縮む。

> **日次はノイズ、週次プールが信号。**
> 成果物は「日次順位表」ではなく **7日移動窓のシェア推移＋信頼区間**にする。
> 順位を言い切らず、**7位ボーダーとの距離とボーダー付近の競合の顔ぶれ**を出す。
> 偽の精度を出さないことが、この設計で最も重要な判断。

### 3.5 交絡要因

Google Trends を却下した論理（LIVE出演で跳ねる）は**X共有にも部分的に効く**。
ライブ出演・CD発売・シリアルコード付き商品の発売日には、その陣営の投票行動が跳ねる。
X共有が優れているのは「投票という具体的行動に紐付いているぶん検索ボリュームより
汚染が軽い」という点だけ。

→ **日次系列にイベントカレンダーを重ねて注記する。事後補正はしない。**

課金票は構造的に過小評価される（1万票買った人も共有投稿は1件）。これは補正できない。
ただし「人数1位」と「票数1位」のズレ自体が読み取るべき情報である。

## 5. 残るリスク

- **Yahooの `totalResultsAvailable` は推定値。** 絶対数として扱わない。
- **8/3〜8/16は欠測。** 全期間の30%。トレンドの起点が8/17以降になる。
- **サービス仕様の変更・終了リスク。** `__NEXT_DATA__` の構造が変わると壊れる。
  パース失敗時は黙って0件にせず、エラーで止めること。
- **正解データが存在しない。** 検証は最終結果が出る9/18以降にしかできない。
- **公開すること自体が観測対象に影響する。** バンドワゴン効果や危機感による動員を
  引き起こし得る。公開範囲は先に決める。

## 6. 出力時の明記事項

集計結果は公式シェア投稿から推定した**投票人数の代理指標**であり、
**公式の投票結果でも得票数でもない**。この旨を出力に必ず明記する。
収集対象は公開投稿のみとし、個々のユーザーの特定・プロファイリングには用いない。
