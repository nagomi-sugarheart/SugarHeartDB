# 日次ワークフロー（ブランチ作成からマージまで）

ユーザーからタスクの依頼（例：ページの作成やバグ修正）があった場合、**必ず以下の1〜6の手順を順番に、途中で省略せずにすべて実行**してください。

## 前提条件
- 常に `dev` ブランチが最新の状態であることを確認してから作業を開始すること。
- **【重要】プランモード・実装開始を問わず、作業の最初に必ず `git fetch origin dev` を実行し、`dev` ブランチの最新状態を確認すること。** ハーネスによって作業ブランチが事前に指定されている場合も同様。`dev` にのみ存在するファイルやCSS変更が作業内容に影響する可能性があるため、確認前に「ファイルが存在しない」などと判断しないこと。

## 実行手順

1. **devブランチの最新状態を確認（必須・最初に行う）:**
   - `git fetch origin dev` を実行する。
   - 作業ブランチがハーネスで指定されている場合は `git merge origin/dev` でマージしてから作業を開始する。
   - 作業ブランチが指定されていない場合は、以下の手順でブランチを作成する:
     - 本日の日付（YYYYMMDD形式）を計算する。
     - `dev` ブランチから `Claude-YYYYMMDD` という名前で新しいブランチを作成し、切り替える。
     - （例：2026年5月20日なら `Claude-20260520`）
     - ※同日にすでにブランチが存在する場合は、そのブランチに切り替える。

2. **タスクの実行:**
   - ユーザーから依頼されたタスク（ページの作成や修正など）を実装する。
   - 仕様書の修正が必要な場合は docs/ フォルダ内の仕様書も修正を行う。
   - 実装したページや機能が `docs/todo.md` に未完了（`[ ]`）として記載されている場合は、該当項目を完了（`[x]`）に更新すること。

3. **関連ページへの自動リンク（※新規ページ作成時のみ）:**
   - 新しいページを作成した場合は、既存のページから関連しそうな場所を探し、今回作成したページへのリンクを自然な形で追記する。

3.5 **sitemap.xml の再生成（※HTMLページの追加・削除・URL変更時のみ）:**
   - `python generate_sitemap.py` を実行して `sitemap.xml` を再生成し、変更をコミットに含める。
   - sitemap.xml は全ページを走査して自動生成されるため、手書きで編集しないこと。

4. **コミット:**
   - 変更内容を確認し、日本語で分かりやすいコミットメッセージをつけて `git commit` する。

5. **PRの作成とマージ:**
   - 作成したブランチをリモートにPushする。
   - `dev` ブランチに向けてPull Requestを作成する。
   - **作成したPRをそのまま `dev` ブランチへマージ（GitHub CLIの `gh pr merge --merge --delete-branch` などを利用）する。**
   - ※もし自動マージのコマンドが使えない環境（Gitコマンドのみの環境）の場合は、ローカルで `dev` ブランチに切り替えて `git merge Claude-YYYYMMDD` を行い、`dev` ブランチをPushすること。

6. **完了報告:**
   - すべての作業、およびマージが完了したことをユーザーに報告する。
